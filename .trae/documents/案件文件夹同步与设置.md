# 案件主文件夹路径设置与文书列表目录同步

## Context

当前文书列表（`GET /api/cases/:id/files`）只读 `file_records` 表，不看磁盘。用户在案件文件夹里直接增删改文件，列表不会反映。用户希望：

- admin 可设置「所有案件的主文件夹根路径」（未来存到局域网共享网盘的挂载路径，如 `/Volumes/xxx`）；
- 每个用户可一键「打开案件文件夹」；
- 文件夹内手动增删改文件，能自动反映到文书列表。

## 已确认决策

1. 子文件夹命名：`案件编号-案件名`（与现有 `folder_path` 命名一致）。
2. 同步方式：打开列表 / 点刷新时自动扫描目录（新增入库、磁盘已删出库）。
3. 保留现有「上传文件」功能。
4. 「打开文件夹」由后端执行系统命令（macOS `open`）。

## 方案设计

### 1. 配置读取（新增 `server/src/services/settings.ts`）
- 新增 `settings` 表（key/value），存 `cases_root`。
- `getSetting(key)` / `setSetting(key,value)` 封装读写。
- `resolveCasesRoot(): string` = 设置值 || `CASES_DIR`（`CASES_DIR` 仍为默认，动态读 DB，不在模块加载时固化）。
- `caseDir(folderPath: string): string`：`target = join(root, basename(folderPath))`；若 `target` 不存在但原 `folder_path` 存在 → 回退原路径（**避免切换根路径后老文件立即失联**）；否则返回 `target`。读与写都走同一函数，保证一致。

### 2. 统一路径解析（改造现有读写磁盘处）
把所有 `caseRow.folder_path` 拼接改为 `caseDir(caseRow.folder_path)`：
- [files.ts](file:///Users/yang/Documents/Tech/AnLi/server/src/routes/files.ts)（上传/下载/打开/重命名/删除/从模板复制/从案件复制，约 12 处）
- [ocr.ts](file:///Users/yang/Documents/Tech/AnLi/server/src/services/ocr.ts#L55-L56)
- [export.ts](file:///Users/yang/Documents/Tech/AnLi/server/src/routes/export.ts#L38-L44)
- [templates.ts](file:///Users/yang/Documents/Tech/AnLi/server/src/routes/templates.ts#L206-L214)
- 建案 [cases.ts](file:///Users/yang/Documents/Tech/AnLi/server/src/routes/cases.ts#L155-L158) 与批量导入 [import.ts](file:///Users/yang/Documents/Tech/AnLi/server/src/routes/import.ts#L74-L75)：`folderPath = join(resolveCasesRoot(), \`${caseNo}-${name}\`)`。

写盘前：仅当 `resolveCasesRoot()` 存在（已挂载）时才允许 `mkdir`；根路径不存在时报错「主文件夹根路径不可用（可能未挂载）」，避免在 `/Volumes/xxx` 下建出本地空目录。

### 3. 文件夹扫描同步（新增 `server/src/services/folder-sync.ts`）
`syncCaseFolder(caseRow)`：
- 取 `dir = caseDir(caseRow.folder_path)`；**若 `dir` 不存在则整案跳过，绝不删除记录**（防止网盘未挂载时清空）。
- 递归遍历（`lstat`，**跳过软链接**）：过滤 `.`/`..`、隐藏文件、`._*`、`~$*`、`.DS_Store`、`Thumbs.db`、`_案件元数据.json`（导出临时文件）、`.Spotlight-V100`、`.fseventsd`、`Icon\r`、`__MACOSX`。
- `rel_path` 统一为 POSIX 分隔 + Unicode NFC 归一化（避免 APFS 的 NFD 造成误删/重复导入）。
- 命中同 `(case_id, rel_path)` → 更新 `size`/`mime_type`/`file_name`；未命中 → `INSERT`（`uploaded_by = NULL`）。
- 磁盘上不存在的 DB 行 → `DELETE`（`file_ocr_text` 随 FK 级联删除）。
- 整个过程包在一个事务内。
- 返回 `{ added, removed, updated, skipped }`。

接口：`GET /api/cases/:id/files` 增加 `?sync=1` 时才执行同步，再返回列表。

### 4. 打开案件文件夹
新增 `POST /api/cases/:id/open-folder`（admin 或案件成员）：
- `dir = caseDir(...)`；不存在则按第 2 节规则尝试创建，不可用则 404。
- 按平台执行：`darwin: open` / `win32: explorer` / 其它 `xdg-open`（与现有 `POST /api/files/:fileId/open` 一致的 `exec` 模式）。
- `logAudit(uid,'case_folder_open','case',cid,dir)`；返回 `{ ok, path }`。

### 5. 数据库变更与迁移（`server/src/db/schema.ts`）
1. 新增 `settings` 表（`key TEXT PRIMARY KEY, value TEXT NOT NULL DEFAULT ''`）。
2. `file_records.uploaded_by` 改为可空：同步入库的文件没有上传人。
   - 修改 `CREATE TABLE` 定义，并新增一次表重建迁移（沿用已有 `PRAGMA table_info` + 重建 + `PRAGMA foreign_keys OFF/ON` 的裸 exec 模式，**不包在 BEGIN 内**）。
   - 重建时显式拷贝 `id` 且保留 `AUTOINCREMENT`，确保 `file_ocr_text.file_id` 不断链；收尾 `PRAGMA foreign_key_check`。
3. `file_records` 加唯一约束 `UNIQUE(case_id, rel_path)`：先删除重复行（保留最小 id）再 `CREATE UNIQUE INDEX IF NOT EXISTS`，防止 upload/rename 与 sync 并发导致重复入库。

## 已知限制（实现时在界面/文案说明）

- 切换根路径后，若网盘未挂载、案件子文件夹未迁移过去，`caseDir` 会回退到原路径，老文件仍可访问；迁移完成后自动切到新根。
- 同步进来的图片是 `pending` 状态，会被现有 OCR 后台 worker 自动识别；一次丢入大量图片可能出现识别高峰。
- 案件改名不会改已生成的文件夹名（现有行为，本次不处理）。
